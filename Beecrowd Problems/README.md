# Beecrowd Problem Solving in C

Welcome to the **Beecrowd Problems** section of the Introduction to Computer Systems (ICS) repository.

This folder is dedicated to practicing programming problems using the C language on Beecrowd, an online platform for programming practice and problem-solving contests.

The goal of this section is to strengthen programming fundamentals, improve logical thinking, and help students gain practical experience by solving problems, submitting solutions, and learning from the results.

## Learning Objectives

By working through this section, students will be able to:

- Understand the basic workflow of an online programming judge.
- Create and use a Beecrowd account for programming practice.
- Solve introductory programming problems using C.
- Apply variables, data types, operators, and formatted input/output.
- Develop algorithms for computational problems.
- Compile, test, and submit C programs.
- Understand accepted and rejected submissions.
- Improve accuracy through repeated practice.
- Build confidence in solving problems independently.

## About Beecrowd

Beecrowd provides programming exercises and an online judging system that evaluates submitted solutions against predefined test cases.

Students can use the platform to practice programming, test their understanding of fundamental concepts, and participate in programming contests.

**Official Website:** https://www.beecrowd.com.br/

## Submission Guidelines

1. Read the complete problem statement.
2. Identify the required input and output formats.
3. Develop the algorithm before coding.
4. Write the solution in C.
5. Compile and test the program locally.
6. Compare the output with the sample output.
7. Check edge cases and constraints.
8. Submit the solution using the required language.
9. Review the verdict and correct errors when necessary.
10. Keep the accepted or improved solution organized in this repository.

## Common Submission Verdicts

| Verdict | Meaning |
|---|---|
| Accepted | The solution passes the judge's required tests |
| Compilation Error | The source code could not be compiled |
| Wrong Answer | The program's output does not satisfy the expected result |
| Time Limit Exceeded | The solution exceeded the permitted execution time |
| Runtime Error | The program encountered an execution-time problem |

The exact verdict labels and available details may vary by judge configuration.

## Best Practices

- Write readable and properly indented C code.
- Use appropriate data types.
- Follow the exact output format required by the problem.
- Avoid unnecessary messages or prompts in online judge submissions.
- Test boundary cases rather than relying only on sample inputs.
- Understand the solution instead of copying code blindly.
- Keep filenames descriptive and consistent.
- Record the problem ID when available.
- Review incorrect submissions to understand the underlying mistake.

# Problem Solving in C

Welcome to the **Problem Solving in C** section of the Introduction to Computer Systems (ICS) repository.

Problem-solving is one of the most important skills in computer programming. It involves understanding a problem, identifying the required inputs and outputs, developing a logical solution, and implementing that solution using a programming language.

This section focuses on applying fundamental C programming concepts to solve mathematical, computational, and real-life problems through structured thinking and practical exercises.

## Learning Objectives

After completing this section, students will be able to:

- Analyze a problem and identify its requirements.
- Determine the necessary inputs, processing steps, and outputs.
- Develop algorithms for simple computational problems.
- Translate problem-solving logic into C programs.
- Use variables, data types, operators, and formatted input/output.
- Apply conditional statements and loops when appropriate.
- Test programs with different inputs.
- Trace program execution and identify logical errors.
- Develop independent problem-solving skills.

## Topics Covered

### 1. Understanding a Problem

- Reading and analyzing problem statements
- Identifying the problem's requirements
- Determining inputs and expected outputs
- Identifying constraints and assumptions
- Breaking a complex task into smaller steps

### 2. Developing the Solution Logic

- Applying the Input-Process-Output (IPO) model
- Designing step-by-step algorithms
- Using flowcharts to represent solutions
- Selecting appropriate variables and data types
- Identifying suitable operators and formulas
- Planning the solution before writing code

### 3. Implementing Solutions in C

- Writing a complete C program
- Using `printf()` and `scanf()`
- Applying arithmetic operators
- Evaluating mathematical expressions
- Using conditional statements for decision-making
- Applying loops to repetitive tasks
- Producing correctly formatted output

### 4. Testing and Debugging

- Compiling and executing programs
- Identifying syntax errors
- Detecting logical errors
- Tracing program execution manually
- Testing normal and boundary inputs
- Comparing actual output with expected output

### 5. Mathematical Problem Solving

- Sum and average calculations
- Area and perimeter calculations
- Unit and temperature conversions
- Simple interest calculations
- Digit-based arithmetic problems
- Number comparisons and basic numerical analysis

### 6. Real-Life Problem Solving

- Calculating shopping bills and totals
- Determining discounts and final prices
- Calculating examination averages
- Converting time into hours, minutes, and seconds
- Calculating travel distance and average speed
- Solving everyday numerical problems using C

## Standard Problem-Solving Workflow

A consistent workflow helps students approach programming problems systematically.

1. **Analyze:** Understand what the problem asks.
2. **Identify:** Determine the inputs and expected outputs.
3. **Plan:** Develop the algorithm and solution logic.
4. **Implement:** Write the solution using C.
5. **Execute:** Compile and run the program.
6. **Test:** Try different inputs and check the results.
7. **Debug:** Correct syntax and logical errors.
8. **Review:** Ensure the solution is readable and meets the requirements.

## How to Compile and Run

Compile the program using GCC:

```bash
gcc ShoppingBill.c -o ShoppingBill
```

Run on Linux or macOS:

```bash
./ShoppingBill
```

Run on Windows:

```bash
ShoppingBill.exe
```

You can also use Code::Blocks or another C-compatible IDE.

## Common Mistakes to Avoid

- Misunderstanding the problem statement.
- Forgetting to initialize variables where necessary.
- Choosing inappropriate data types.
- Using incorrect formulas or operators.
- Confusing assignment (`=`) with equality (`==`).
- Ignoring integer division and type conversion.
- Forgetting to test boundary cases.
- Writing code without checking the expected output.

## Recommended Practice Method

- Solve the problem on paper before coding.
- Write the input, process, and output separately.
- Develop the algorithm before implementation.
- Start with a simple solution and improve it gradually.
- Trace the program manually using sample values.
- Test different inputs, including edge cases.
- Write your own solution before reviewing other implementations.
